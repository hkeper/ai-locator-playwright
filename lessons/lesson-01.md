# Урок 1. Скелет проекта и первый тест

> Дата: 2026-09-26. Тег: `lesson-01`. Конспект восстановлен по заметкам.

## Зачем

Нужен минимальный рабочий проект: зависимости, игнорируемые файлы и тест, который проходит.
Всё следующее строится поверх этого скелета.

## Теория

### package.json построчно

- **name, version, private.** `private: true` защищает от случайной публикации пакета в npm.
- **scripts.** Короткие команды: `npm test` запускает `playwright test`.
- **devDependencies.** Пакеты, нужные только для разработки и тестов, а не для работы приложения.

### @playwright/test и его зависимости

Ставится один пакет `@playwright/test`, а вместе с ним транзитивно приходят `playwright` и `playwright-core`.
`playwright-core` содержит движок управления браузерами, `@playwright/test` добавляет раннер тестов и `expect`.
Браузеры ставятся отдельной командой `npx playwright install`.
Документация: [Installation](https://playwright.dev/docs/intro).

### .gitignore

В git не попадают файлы, которые можно восстановить или которые зависят от машины:

```
node_modules/
test-results/
playwright-report/
```

Документация: [gitignore](https://git-scm.com/docs/gitignore).

### Web-first assertions

`expect(locator).toBeVisible()` не проверяет состояние один раз, а ждёт.
Первая проверка выполняется сразу, затем повторы с паузами 20, 50, 100, 100 и 500 мс, дальше каждые 500 мс.
Ожидание длится до `expect.timeout`, по умолчанию 5 секунд.
Поэтому ручные `waitForTimeout` в тестах не нужны.
Документация: [Assertions](https://playwright.dev/docs/test-assertions).

### Воркеры и параллельность

По умолчанию разные файлы тестов идут параллельно в разных воркерах.
Тесты внутри одного файла идут последовательно, пока не включён `fullyParallel`.
Документация: [Parallelism](https://playwright.dev/docs/test-parallel).

### Как искать элементы

| Способ | Плюсы | Минусы |
|---|---|---|
| `id` и CSS | быстро и привычно | ломается при смене вёрстки |
| `getByRole` | проверяет доступность, рекомендуется Playwright | имя элемента зависит от языка интерфейса |
| `data-test` | стабилен и не зависит от языка | атрибут должен добавить разработчик |

Аргумент из обсуждения: при нескольких языках интерфейса `getByRole` с текстом ломается, поэтому для проекта удобнее `data-test`.
Документация: [Locators](https://playwright.dev/docs/locators).

## Код урока

Тесты страницы входа saucedemo.com лежат в `tests/login.spec.ts`. Первый тест проверяет заголовок страницы:

```ts
import {test, expect} from '@playwright/test';

test('login page opens', async ({page}) => {
  await page.goto('https://www.saucedemo.com/');
  await expect(page).toHaveTitle('Swag Labs');
});
```

Второй тест проверяет, что видны поле имени пользователя и кнопка входа.
