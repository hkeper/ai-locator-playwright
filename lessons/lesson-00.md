## Теория

### package.json

Это описание проекта: имя, скрипты и список зависимостей с допустимыми версиями.
Файл пишет человек, npm только дополняет его командами вроде `npm install -D пакет`.
Документация: [package.json](https://docs.npmjs.com/cli/configuring-npm/package-json).

### package-lock.json

Lock-файл фиксирует точные версии всех пакетов, включая транзитивные, то есть зависимости зависимостей.
Благодаря ему у всех разработчиков и на CI ставится одно и то же дерево пакетов.
Lock-файл коммитится в git. Вручную его не правят.
Документация: [package-lock.json](https://docs.npmjs.com/cli/configuring-npm/package-lock-json).

### Semver-диапазоны

Версия состоит из трёх чисел: `MAJOR.MINOR.PATCH`.
MAJOR меняется при несовместимых изменениях, MINOR при новых возможностях, PATCH при исправлениях.

| Запись | Что разрешает |
|---|---|
| `1.63.0` | только эту версию |
| `~1.63.0` | только патчи: `1.63.x` |
| `^1.63.0` | минорные и патчи: `1.x.x` от `1.63.0`, но не `2.0.0` |

Проверить диапазон можно в [калькуляторе semver](https://semver.npmjs.com/).

### npm install и npm ci

| Команда | Что делает | Когда использовать |
|---|---|---|
| `npm install` | ставит пакеты по диапазонам и может обновить lock-файл | при разработке и добавлении пакетов |
| `npm ci` | удаляет `node_modules` и ставит строго по lock-файлу, падает при расхождении с package.json | на CI и для чистой установки |

Документация: [npm ci](https://docs.npmjs.com/cli/commands/npm-ci).

### node_modules/.bin

Пакеты с командами кладут исполняемые файлы в `node_modules/.bin`.
Скрипты из `package.json` видят эту папку, поэтому в `"test": "playwright test"` не нужен полный путь.
Вне скриптов локальную команду запускают через `npx`, например `npx playwright --version`.
